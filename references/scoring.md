# 评分与推荐

先处理硬约束，再计算排序分。任一必须用例失败的模型不能成为主推荐，即使速度更快或价格更低。

## 脚本指标

- `pass_rate`: 自动校验通过次数 / 总调用次数。
- `success_rate`: 获得可解析聊天响应的次数 / 总调用次数。
- `latency_p50_ms`、`latency_p95_ms`: 完整响应耗时的中位数与近似 95 分位。
- `input_tokens`、`output_tokens`: 端点返回的 usage 累计值；供应商未返回时为未知。
- `estimated_cost`: 仅在价格表和 Token 用量都存在时计算。

脚本默认排序为：通过率降序、成功率降序、P50 延迟升序。它不生成一个看似精确但难以解释的综合分。

## 价格表

价格文件以每百万 Token 的相同货币单位计价：

```json
{
  "model-a": {"input_per_million": 1.5, "output_per_million": 6.0, "currency": "CNY"},
  "model-b": {"input_per_million": 0.8, "output_per_million": 3.2, "currency": "CNY"}
}
```

价格应来自测试当天的供应商公开资料或用户账单，并在报告外记录来源和日期。不同币种不能直接排序。缓存、阶梯价、长上下文附加费和渠道折扣未计入时必须注明。

## 推荐结论

优先给出可操作的帕累托选择：

- 主模型：满足全部硬约束，质量最稳定。
- 经济模型：达到质量底线时成本更低。
- 低延迟模型：达到质量底线时延迟更低。
- 备选模型：主模型不可用时仍满足关键约束。

样本量小于每模型 20 次时，不把微小延迟差异描述为稳定性能差异。跨时段、跨地区和跨供应商端点的网关条件可能影响延迟，应在目标部署环境复测。
